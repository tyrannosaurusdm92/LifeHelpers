# Dossier Requirements — William, Jasper, and Shared Onyx

## Shared rule: one canonical Onyx

William and Jasper use the **same canonical Onyx identity and shared catalog definition**. Their profiles must never create visually different base versions of Onyx. Clothing, layouts, owned objects, and optional profile-specific state can differ, but Onyx's locked body/face/fur/eyes/whiskers/tail/personality/history remain one canon.

## Profile privacy

The dossier requires profile-specific namespaces for:

- conversations,
- journals,
- check-ins,
- DBT/ADHD history,
- medication information,
- diabetes information,
- appointments,
- tasks,
- currency,
- inventory ownership,
- room layouts,
- wardrobe,
- Studio projects,
- preferences.

Only intentionally shared eligible data may cross profiles, such as selected designs/layouts, catalog configuration, delivery records, or creator attribution. Shared layouts must never carry journals, care data, appointments, currency, or personal tasks.

## William

### What the dossier explicitly requires

- William is one of the two authenticated Onyx profiles.
- William receives the same canonical Onyx, not a separately modeled cat.
- William's private care/conversation/project/economy data remains separate from Jasper's.
- William participates in the recurring AC/fan login ritual described below.
- Room/layout systems must support wheelchair-aware route checking and wheelchair-view presentation guides.

### Current project calibration context supplied outside the dossier

These facts come from the current project conversation, **not from the dossier**, and should remain clearly labeled as supplemental reference:

- William is 5 ft 4 in tall.
- William stated a body weight of 500 lb.
- William described having a long torso.
- William's wheelchair is specifically sized to fit him.
- Real Onyx photos/videos include Onyx in William's arms/lap and on/near the wheelchair; these can be used as secondary relative-scale evidence.

These facts are appropriate for later scale/accessibility/reference comparison. They are **not permission to invent a William avatar body model or wheelchair dimensions** without explicit measurements or a separate avatar-design request.

## Jasper

### What the dossier explicitly requires

- Jasper is the second authenticated Onyx profile.
- Jasper receives the same canonical Onyx.
- Jasper's private data remains separate from William's.
- Jasper participates in the same AC/fan login ritual.
- Jasper's private support tools may include blood-glucose reminders/logs, meal context, symptoms, hydration, appointments, labs, exports, and healthcare-team target ranges.

The dossier does **not** provide a physical Jasper avatar specification. Do not infer Jasper's body proportions, height, weight, mobility equipment, or visual model from these support requirements.

## AC-and-fan login ritual for both profiles

Every successful William or Jasper login intentionally starts with:

- Onyx-room AC: **OFF**,
- all Onyx-room fans: **OFF**,
- immediate Onyx behavior cue: `climate_control_request`,
- default line: **“Hey, turn on my AC and fan please.”**

Suggested performance language includes:

- looking toward the user,
- expectant meow/yowl,
- judgmental or insistent pause,
- glance toward the controls,
- tail-tip punctuation.

If the user turns climate controls on, Onyx may purr, slow-blink, chirp/meow approvingly, or give judgmental acceptance before resuming activity.

### Critical rule

This ritual is **not a need**. There is no temperature, comfort, health, safety, affection, attention, or energy meter behind it. Either user may ignore the request without harm, guilt, lost progress, or neglect consequences.

## Start Day

For each profile, Start Day is a safe/idempotent refresh of optional prompts, dialogue, tasks, journaling, discounts, and interactions. It preserves inventory, purchases, layouts, projects, and progress, and never creates an absence-repair obligation.

## Current Cat Only package boundary

None of these William/Jasper profile systems need to be implemented in the Cat Only appearance viewer while Onyx's physical form is still being approved. Their inclusion here is documentation so later integration does not accidentally:

- merge private data,
- fork Onyx's canonical appearance,
- introduce punitive needs,
- omit the login ritual,
- or forget wheelchair-aware layout/accessibility expectations.
