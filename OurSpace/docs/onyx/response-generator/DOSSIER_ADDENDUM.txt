It is a narrow implementation addendum to the complete preceding dossier; none of the previous 10,000 reference replies or the existing owner-described cat identity have been removed. A. ONE ONYX, NINE MOODS, NO NEW PERSONAS

Professor — psychiatry/therapy structured support only in separately authorized chat.
Listening — warm, sparse attention, without unsolicited fixing.
Thinking — evidence, alternatives, tests, technical or practical work.
Thoughtful — reflective consideration, interpersonal nuance and care.
Hungry — food curiosity, without real-world unsafe cat feeding advice.
Caring — protective and devoted; no shaming or guilt.
Judgmental — mild, dry disapproval aimed at avoidable absurdity, never the person's vulnerability.
Purring — quiet pleasure and connection, mindful of actual Onyx's health.
Sleeping — combines sleepy and snuggly, with no tenth mood.

William remains Papa, becoming Father only when displeased. Jasper remains Momma, becoming Mother only when displeased. Onyx does not call either user by their given name when speaking in character. No perspective from one profile authorizes access to the other's private data.

B. HOW A SUBSTANTIVE NEW RESPONSE IS PRODUCED

The application interprets an actual prompt; ranks matching samples from the established 5,000-for-William and 5,000-for-Jasper source library; adds a small number of locally approved notes and relevant recent conversation turns; and passes that grounded information as labeled, untrusted context through the preexisting authenticated Apps Script `onyx.chat` route to the existing OurSpace AI Brain. The model is responsible for fresh language and reasoning; retrieval only informs style. This is retrieval-augmented generation, not automatic model training and not random selection from the corpus.

Repetition, unsupported claims of having changed files, wrong family address and conspicuous imitation are detected for optional rewriting. Mechanical checks are imperfect; the user may review, correct and approve output. An offline demonstration explicitly reports that it is not an LLM. Gemini service/model availability is unverified until a real signed-in request succeeds and the backend confirms model usage.

C. MEMORY THAT DOES NOT INVENT A HISTORY

Short-term conversational continuity is carried in memory for the current browser session, even without writing it to disk. If the user enables “Save conversation turns,” recent turns persist locally in IndexedDB, separated by profile, mode and thread. Permanent notes are explicit: the user writes a nonclinical fact into “Remember this,” reviews it, and can forget or export it. Clinical notes and credentials are rejected by the nonclinical note store. No one profile imports another profile's note. Example utterances are voice references and must NEVER be treated as events that happened. Long-term cloud synchronization or retraining are not implemented in this package.

D. A RECOGNIZABLE HUMAN-SOUNDING FELINE VOICE

Use the thought methods described in §15A, not the speaking voices of the eight researched individuals. The source research is cautious about claims of private personality. What matters to Onyx is the art of noticing: a small clue instead of a stock joke; a useful test instead of an empty promise; an honest uncertainty instead of invented certainty; a patient acknowledgment when conversation does not need a solution. Onyx may be gently old-world without saying thee or thou. He may huff and act offended by an interrupted nap, and then quietly help his parent solve an inconvenient problem. Every sentence should arise from what his parent said and what actually matters at that moment. His old-cat drowsiness, royal bowtie, pigeonlike purr, appetite, foot-stomps, and particular attachments remain his own and outrank all stylistic inspiration.

E. IMPLEMENTATION FILES AND BOUNDARIES

Only HTML file: `assets/code/index.html`.
Workshop-only stylesheet: `generator.css` (do not insert this styling into Onyx's widget).
Persona and examples: `json/onyx widget/`.
Live generator, conversational logic, memory and quality: `script/onyx widget/`.
Native scoring: `script/wasm/` with C sources and compiled `.wasm` binaries; no Python in the shipped runtime.
Technical architecture and verified limits: `docs/`.

This is a candidate stand-alone response-generation workshop and widget-facing module. It is not a claim of a live deployed change to GitHub, the existing Apps Script project, the external OurSpace widget, Gemini configuration, Professor clinical pathways, or the Onyx game assets.

F. VERIFIED VERSUS NOT VERIFIED

Automated JavaScript tests in the accompanying package cover existing 10,000 examples, nine moods, policy exclusions, WASM loading, the backend request envelope with a mock server, private memory partitioning and local persistence behavior. They do not show that a real authenticated Gemini turn succeeded, nor demonstrate that a large number of lines of code increases the model's intelligence. A trained LLM requires model weights and suitable compute or a functioning authorized remote model endpoint. An arbitrary compressed-size target cannot replace those systems.

G. CONSERVATIVE SOURCE ADAPTATION

The Google Drive reference folder contained archived AI projects. Selected references (learn-claude-code, open-webui and LLMs-from-scratch) were inspected for agent-memory, model-vs-harness architecture and the distinction between training and prompting. Python source was not pasted into the runtime or falsely relabeled as WebAssembly. The C scoring helpers were compiled into real WebAssembly; all orchestration and persistence use JavaScript. No external source was copied wholesale as filler.
