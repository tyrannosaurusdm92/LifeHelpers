# Onyx Work fullscreen integration — pass 7

## What was merged

The Work package is embedded in Onyx's fullscreen iframe shell. Its `css/`, `js/`, `json/`, and `moods/` directories remain at the package root so the Work page's relative references continue to resolve. The original standalone Work page is retained as `docs/WORK_TAB_SOURCE.txt`, leaving `onyx.html` as the sole HTML file.

The fullscreen entry is generated by the Onyx tab UI and opens the Work shell. Its fixed red X sits at the top-right and returns to the module. The Work workspace keeps its six server areas, nested tabs, project catalog, attachments, image mode, persistence, and existing authenticated backend contract.

## Design palette

The Onyx module sends its current palette to the Work iframe at load and after each `onyx-module-design-change` event. Work applies the provided panel, text, border, header, surface, rail, chat, message, input, button, active, link, focus, and scrollbar colors to its shared CSS variables. This carries grayscale and color choices into Work fullscreen while preserving the Work portrait art.

The palette change event remains shared by all existing module tabs. The embedded Work surface does not add a new chat backend or replace Onyx's existing backend connection.

## User-facing labels and fullscreen behavior

- **Virtual Health** is the Health tab and the fullscreen health shell label.
- **Feed Him MEOW** is the Leisure fullscreen button and fullscreen label. Its fullscreen iframe body is intentionally blank; the outer red X remains available.
- **Work** opens the complete Work workspace fullscreen, with the red X at the top-right.

## Package validation contract

- `onyx.html` is the only `.html` file.
- Work JavaScript, CSS, JSON, and mood-image references resolve within the merged package.
- The existing frame-by-frame animation research assets, mood profiles, and base-cat assets remain in place.
